# Location Popularity API

Django REST API для роботи з локаціями та їхньою популярністю. Проєкт використовує PostgreSQL для основних даних, Redis для кешу та Mailpit для локальної перевірки електронних листів.

## Потрібно для запуску

- Docker Desktop із Docker Compose.
- Git, щоб клонувати репозиторій.

PostgreSQL, Redis і Python окремо встановлювати на комп’ютер не потрібно: вони запускаються в Docker.

## Перший запуск

Відкрий термінал у папці проєкту та виконай кроки по черзі.

1. Створи локальний файл налаштувань із прикладу:

   ```bash
   cp .env.example .env
   ```

2. Відкрий `.env` і заміни `DJANGO_SECRET_KEY` та `POSTGRES_PASSWORD` на власні значення. Файл `.env` містить локальні секрети — не додавай його до Git.

3. Збери образ Django:

   ```bash
   docker compose build web
   ```

4. Запусти PostgreSQL, Redis і Mailpit:

   ```bash
   docker compose up -d db redis mailpit
   ```

5. Застосуй міграції Django до PostgreSQL:

   ```bash
   docker compose run --rm web python manage.py migrate
   ```

6. Запусти вебзастосунок:

   ```bash
   docker compose up -d web
   ```

7. Створи адміністратора:

   ```bash
   docker compose exec web python manage.py createsuperuser
   ```

Після цього відкрий:

- Django admin: <http://localhost:8000/admin/>
- Mailpit — тестова поштова скринька: <http://localhost:8025/>

## Корисні команди

Переглянути стан контейнерів:

```bash
docker compose ps
```

Переглянути журнал Django:

```bash
docker compose logs -f web
```

Застосувати нові міграції:

```bash
docker compose exec web python manage.py migrate
```

Зупинити контейнери, зберігши дані PostgreSQL:

```bash
docker compose down
```

PostgreSQL зберігає дані в Docker volume `postgres_data`. Щоб видалити також цей volume і всі дані бази, використовуй `docker compose down -v`.

## Перевірка скидання пароля без фронтенду

1. Переконайся, що контейнери запущені, а потім відкрий Mailpit: <http://localhost:8025/>.
2. Надішли POST-запит на `/api/auth/password-reset/` із JSON, наприклад:

   ```json
   {"email": "адреса_користувача@example.com"}
   ```

   Для локального запиту спершу отримай CSRF-токен через `GET /api/auth/csrf/`, збережи cookie та передай значення `csrfToken` у заголовку `X-CSRFToken`.
3. Відкрий лист «Скидання пароля» в Mailpit. У ньому є `uid` і `token` для наступного запиту.
4. Надішли POST-запит на `/api/auth/password-reset/confirm/` із JSON:

   ```json
   {
     "uid": "значення_з_листа",
     "token": "значення_з_листа",
     "new_password": "Новий-Складний-Пароль-482!"
   }
   ```

   До цього запиту також передай CSRF cookie та заголовок `X-CSRFToken`. Успішна відповідь означає, що пароль змінено. Після цього перевір вхід із новим паролем через `/api/auth/login/`.

Якщо вказати адресу, якої немає в системі, API поверне таку саму відповідь, як і для наявної адреси, але лист не надішле. Токен має обмежений строк дії; після успішної зміни пароля його повторне використання відхиляється.

## Категорії

`GET /api/categories/` повертає список категорій для всіх користувачів. Список поділений на сторінки по 10 записів; можна передати `page` і `page_size`, наприклад `/api/categories/?page=2&page_size=5`. Максимальний розмір сторінки — 100. `GET /api/categories/{id}/` повертає окрему категорію.

Лише адміністратор (`is_staff=True`) може створювати категорії через `POST /api/categories/`, змінювати їх через `PUT` або `PATCH /api/categories/{id}/` та видаляти через `DELETE /api/categories/{id}/`. У запиті на створення чи зміну передавай JSON із полем `name`, наприклад `{"name": "Музеї"}`. Для цих запитів потрібні сесія та CSRF-токен, як описано вище.

Порожні назви й назви, які вже існують без урахування регістру, повертають помилку 400. Категорію з локаціями видалити не можна: спочатку перенеси локації до іншої категорії.

## Локації

`GET /api/locations/` повертає активні локації всім користувачам, по 10 на сторінку. Параметри `page` і `page_size` працюють так само, як для категорій. `GET /api/locations/{id}/` повертає деталі активної локації.

Список підтримує `search` (пошук у назві й описі без урахування регістру), `category` та `author` (їхні ID), `rating_min`, `rating_max` і `ordering`. У `ordering` можна передати `created_at`, `rating` або `popularity`; знак `-` означає порядок від більшого до меншого. За однакових значень додатково застосовується порядок за ID. Параметри працюють разом і застосовуються до пагінації. Наприклад:

```text
/api/locations/?search=парк&category=1&author=2&rating_min=4&ordering=-popularity&page=2&page_size=5
```

Максимальне значення `page_size` — 100. Без `ordering` список упорядкований від новіших локацій до старіших.

Авторизований користувач створює локацію через `POST /api/locations/`. Приклад JSON:

```json
{
  "name": "Парк Шевченка",
  "description": "Міський парк",
  "category": 1,
  "address": "Київ, вулиця Прикладна, 1",
  "latitude": "50.450001",
  "longitude": "30.523333"
}
```

`category` — ID наявної категорії. Координати мають бути в межах від -90 до 90 для широти й від -180 до 180 для довготи. Сервер сам записує автора й дати; клієнт не може змінити ці поля або `deleted_at`.

Автор чи адміністратор може змінити свою локацію через `PUT` або `PATCH /api/locations/{id}/` і видалити через `DELETE /api/locations/{id}/`. Для цих запитів потрібні сесія та CSRF-токен. Видалення лише заповнює `deleted_at`: запис залишається в базі, але список і деталі його більше не показують. Нові відгуки й голоси для такої локації також заборонені.

## Перегляди, рейтинг і популярність

Успішний `GET /api/locations/{id}/` зараховує перегляд. Список локацій, `HEAD`, неіснуючі чи видалені локації переглядів не додають. Для користувача використовується його ID, для гостя — випадковий ідентифікатор у Django-сесії. Redis дозволяє один перегляд однієї локації від одного відвідувача протягом 3600 секунд; лише зараховані перегляди записуються до PostgreSQL. Повторний запит у цю годину повертає деталі без нового запису. Очищення cookies чи інкогніто створює нового гостя; після входу той самий відвідувач може дати окремий перегляд як авторизований користувач.

Список і деталі локацій містять обчислені поля `rating` (середня оцінка), `review_count`, `views_last_7_days` і `popularity`. Формула: `popularity = rating × review_count + views_last_7_days`. Оцінки й кількість відгуків враховуються за весь час, перегляди — за рухомі останні 168 годин. Для локації без відгуків чи переглядів відповідні значення дорівнюють нулю. Ці показники обчислюються в запиті до бази, тому можуть використовуватися для фільтрації та сортування до пагінації.

Відповіді списку локацій кешуються в Redis на 60 секунд. Ключ ураховує всі параметри вибірки, сторінку, розмір сторінки та адресу запиту. Після створення, зміни чи видалення локації, зміни категорії або відгуку та нового зарахованого перегляду версія кешу збільшується **після успішного збереження транзакції**. Наступний запит читає актуальні дані; старі ключі зникають після завершення TTL. Redis не очищується цілком, тому погодинні ключі переглядів залишаються чинними. Короткий TTL також оновлює список, коли давні перегляди виходять за межі 168 годин.

## Відгуки та голоси

`GET /api/locations/{id}/reviews/` показує відгуки локації всім користувачам. Список має пагінацію через `page` і `page_size`; кожен відгук містить `likes_count` та `dislikes_count`.

Авторизований користувач додає відгук через `POST /api/locations/{id}/reviews/`:

```json
{"rating": 5, "comment": "Гарне місце для прогулянки"}
```

Оцінка має бути цілим числом від 1 до 5, коментар — непорожнім. Автор встановлюється із сесії. Для однієї локації користувач може створити лише один відгук; повторний запит повертає 400.

Авторизований користувач голосує через `PUT /api/reviews/{id}/vote/` з JSON `{"vote": 1}` для Like або `{"vote": -1}` для Dislike. Повторний такий самий голос не створює нового запису; інше значення змінює поточний голос. `DELETE /api/reviews/{id}/vote/` скасовує свій голос. Запити, що змінюють дані, потребують сесії та CSRF-токена. Для видаленої локації список відгуків і голосування повертають 404.

## Налаштування для розробки

Сервіси проєкту описані в `docker-compose.yml`: Django (`web`), PostgreSQL (`db`), Redis (`redis`) і Mailpit (`mailpit`). У контейнері Django підключається до PostgreSQL та Redis за назвами сервісів. Листи, надіслані Django під час локальної розробки, потрапляють у Mailpit і не відправляються реальним одержувачам.

Зразок змінних середовища зберігається в `.env.example`. Локальні значення та секрети зберігай у `.env`; цей файл виключений із Git.
